Methodik

Daten

Alle Daten stammen aus der Timetables-API der Deutschen Bahn (Sollfahrplan und Echtzeitänderungen), Lizenz CC BY 4.0. Wir nutzen das öffentliche Archiv piebro/deutsche-bahn-data, das die API rund um die Uhr für alle deutschen Bahnhöfe abfragt. Abgeschlossene Monate kommen aus den aufbereiteten Monatsdateien, der laufende Monat wird aus den rohen API-Antworten gelesen. Jeder Halt hat eine eindeutige ID und wird genau einmal gezählt.

Es zählen nur planmäßige Halte (die im Sollfahrplan stehen); zusätzliche Halte, die erst am Tag dazukommen, zählen nicht. Die Verspätung eines Halts ist die zuletzt gemeldete geänderte Ankunftszeit minus der geplanten Ankunftszeit. Achtung: Die Spalte delay_in_min im Archiv bevorzugt die Abfahrtsverspätung, deshalb berechnen wir die Ankunftsverspätung selbst. Hat die API nie eine Änderung gemeldet, gilt der Zug als pünktlich. Weil die API abgefragt und nicht gestreamt wird, kann gelegentlich eine späte Änderung fehlen; die Zahlen können daher leicht von der offiziellen Pünktlichkeitsstatistik der DB abweichen.

Fairness

Bahnhöfe am Ende langer Strecken erben Verspätungen von weiter vorne, und große Knoten sehen viel mehr Züge als kleine Bahnhöfe. Diese Liga misst bewusst, was ein Fahrgast am Bahnsteig erlebt, nicht wer eine Verspätung verursacht hat. Die Ursachen stehen nicht in den Daten, eine Platzierung ist also nie eine Schuldzuweisung. Denkbar ist später eine Tabelle "Heimleistung", die nur die am Bahnhof selbst entstandene Verspätung wertet.

Prognose für morgen

Jede Bahnhofsseite zeigt eine Prognose im Stil eines Vorhersagemarkts: Wie wahrscheinlich schafft der Bahnhof morgen mindestens 0,60 Punkte? Das Modell ist bewusst einfach: Es nimmt die gewerteten Tage der letzten 8 Wochen, gewichtet jüngere Tage stärker (ein zwei Wochen alter Tag zählt halb) und den gleichen Wochentag doppelt, weil Wochenenden deutlich pünktlicher sind. Die Wahrscheinlichkeit ist der gewichtete Anteil der Tage über der Schwelle, leicht Richtung 50 % gezogen. Über alle Bahnhöfe erreicht es einen Brier-Score von etwa 0,18 (Münzwurf: 0,25; für alle die gleiche Quote: 0,24), es ist also nützlich, aber weit weg von sicher. Halten an einem Bahnhof gerade keine ICE/IC, gibt es keine Prognose. Keine Wetten, kein Geld.

Prüfung

Vor jeder Veröffentlichung prüft ein unabhängiges Prüfprogramm die gesamte Historie: Es rechnet alle Tagespunkte, Tabellen, Mitgliedschaften, Auf- und Abstiege, Relegationen und Nachrücker aus den Rohdaten nach und erklärt jeden Ligawechsel. Findet es auch nur einen Widerspruch, wird nichts veröffentlicht.

Aktualisierung

Die Seite wird automatisch per GitHub Actions neu gebaut, alle drei Stunden. Die Tabelle der laufenden Woche ist live und ändert sich nach jedem Wertungstag; Auf- und Abstieg gibt es nach dem Sonntag.

Keine Verbindung zur DB

Dies ist ein unabhängiges Fanprojekt, nicht verbunden mit der Deutschen Bahn AG und nicht von ihr unterstützt. Alle Wappen auf dieser Seite sind eigene Entwürfe. Keine Wetten, keine Preise, nur Ehre.

Methodology

Data

All data comes from the Deutsche Bahn Timetables API (planned timetable and live changes), licensed CC BY 4.0. We use the public archive piebro/deutsche-bahn-data, which polls the API for every German station around the clock. Complete months come from its processed monthly files; the running month is parsed from the raw API responses. Each stop has a unique id and is counted once.

Only scheduled stops count (those in the planned timetable), so extra stops added on the day do not. A stop's delay is its last known changed arrival time minus its planned arrival time. Note that the archive's own delay_in_min column prefers the departure delay, so we compute the arrival delay ourselves. If the API never reported a change, the train is treated as on time. Because the API is polled rather than streamed, a late change can occasionally be missed, so the numbers can differ slightly from DB's official punctuality statistics.

Fairness

Stations at the end of long routes inherit delays from upstream, and big hubs see far more trains than small ones. This league deliberately measures what a passenger standing on the platform experiences, not who caused a delay. Delay causes are unknown in this data, so a ranking is never blame. A possible later addition is a "Heimleistung" table that scores only the delay added at the station itself.

Forecast for tomorrow

Every station page shows a forecast: how likely is the station to score at least 0.60 tomorrow? The model is deliberately simple. It takes the scored days of the last 8 weeks, weights recent days more (a day two weeks old counts half) and the same weekday double, because weekends are clearly more punctual. The probability is the weighted share of days above the threshold, pulled slightly towards 50%. Across all stations it reaches a Brier score of about 0.18 (coin flip: 0.25; the same odds for everyone: 0.24), so it is useful but far from certain. When no ICE/IC trains currently stop at a station, there is no forecast. No betting, no money.

Audit

Before every publish, an independent checker re-derives the entire history from the raw daily data: points, tables, memberships, promotions, relegations, deciders and gap fills, and it requires every league change to be explained. If it finds a single contradiction, nothing is published.

Updates

The site is rebuilt automatically by GitHub Actions every three hours. The current week's table is live and will change after every scoring day; promotion and relegation are applied after Sunday.
